Moving the Apothecary off tea.laurelate.com

Status: blocked on one Netlify click · derived Sep 21, 2026 against live DNS and the Netlify origin

Goal: this app answers on apothecary.rosettawang.org and tea.laurelate.com stops existing. Rosetta asked for a clean break — no redirect — so old links will simply fail to resolve.

Order matters, and getting it wrong takes the app offline

Netlify routes by Host header. Proved Sep 21, 2026 by sending each Host to Netlify's IP directly: Host: apothecary.rosettawang.org returns 404 Not Found, while Host: gorgeous-moxie-b6f8eb.netlify.app returns 301. So until Netlify is told the new name, it will not serve it — and deleting tea first would leave the app reachable at neither name.

Where it stands

StepState
apothecary CNAME on the rosettawang.org zone Done Sep 21, 2026. CNAME → gorgeous-moxie-b6f8eb.netlify.app, DNS only. Resolves to 52.52.192.191 / 13.52.188.95 via 1.1.1.1. Proxying was left off deliberately: Netlify issues its own certificate, and an orange cloud in front of it breaks that validation.
Netlify custom domain Not done — this is the blocker. The certificate served for the new hostname is CN=*.netlify.app, Netlify's generic wildcard, which does not cover apothecary.rosettawang.org. A browser opening it today gets a certificate warning.
Delete tea from the laurelate.com zone Not done, and deliberately last. tea.laurelate.com still returns 200 and is untouched.

What to do, in this order

  1. Rosetta: add apothecary.rosettawang.org in Netlify — the gorgeous-moxie-b6f8eb site, Domain management, Add a domain.
  2. Check the certificate actually covers the new name, not just that the page loads. This is the step that tells you Netlify really accepted the domain: 
    echo | openssl s_client -connect apothecary.rosettawang.org:443 \
  -servername apothecary.rosettawang.org 2>/dev/null | openssl x509 -noout -subject

    It must name apothecary.rosettawang.org. While it still says CN=*.netlify.app, Netlify has not finished.

  3. Confirm the app renders, not just that something answers: 
    curl -sL https://apothecary.rosettawang.org/ | grep -o '<title>[^<]*</title>'

    Expect <title>Laurelate journal</title>.

  4. Then delete the tea CNAME from the laurelate.com zone. 22 of 200 records were in use on Sep 21, 2026; it is the CNAME pointing at gorgeous-moxie-b6f8eb.netlify.app.
  5. Remove tea.laurelate.com from Netlify too, or it sits in that site's domain list claiming a hostname that no longer resolves — which is the sort of thing that confuses the next person to open the dashboard.

What a clean break costs

Rosetta chose this over a redirect, and it is the simpler end state. The cost, recorded so it is not a surprise later: every existing link, bookmark and QR code pointing at tea.laurelate.com stops working, with a DNS failure rather than a friendly page. Worth a thought about whether that URL was ever printed on anything, or sent to anyone who uses the journal — the app holds accounts, so some people may have it saved.

If that turns out to matter, the reversal is cheap while the record still exists: keep tea, turn the proxy on, and add a Cloudflare redirect rule to the new host. That option disappears once the record is deleted, which is the one argument for deciding now rather than later.
