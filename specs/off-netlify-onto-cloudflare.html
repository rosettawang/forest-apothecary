Taking the Apothecary off Netlify and onto Cloudflare

Status: open · derived Sep 21, 2026 by reading every function in this repo

Goal: this app runs entirely on the Cloudflare account that already hosts laurelate-website and iceland-doc — one dashboard, one bill, one place to look when something breaks — with Supabase still doing the data and nothing about the app's behaviour changing.

Nothing is broken. This is consolidation, and it is optional.

Netlify works. The honest reason to do this is that two hosting accounts is one more than necessary and the Cloudflare side is already familiar. The honest reason not to is that the app holds real accounts and personal wellness journals, and auth and delete-account are not code to break casually. If it never gets done, nothing bad happens.

Why the functions are a port and not a rename

All ten are Netlify Functions v1. Every one is exports.handler = async (event) => ({ statusCode, headers, body }) — CommonJS, an event object in, a plain object out. Workers want export default { async fetch(request, env, ctx) } returning a real Response. Had they been v2 (export default async (req, context)) this would have been close to a no-op. They are not.

One function needs more than mechanical translation. auth.js opens with require('https') and talks to Supabase through Node's https.request, sizing the body with Buffer.byteLength. nodejs_compat would probably carry it, but the right move is to rewrite that helper as one fetch call — it is calling a REST API, the rewrite is shorter than the original, and it removes the only Node-API dependency in the app. Check the others for the same pattern rather than assuming auth.js is alone in it.

The reminder job can double-send SMS to real people

send-reminders runs every fifteen minutes and sends text messages through Twilio. If the Netlify schedule and a Cloudflare Cron Trigger are ever both live, every reminder goes out twice — to real phone numbers, with no way to recall them.

So: never have both enabled. Comment the [functions."send-reminders"] block out of netlify.toml and redeploy Netlify before adding the Cloudflare cron, and treat that as its own step with its own verification rather than a detail inside a larger one. Everything else in this migration is reversible; this is the part that reaches strangers' phones.

Build order

  1. Scaffold, without touching Netlify. wrangler.jsonc with a static-assets binding for the repo root, plus src/worker.js holding a path router. Deploy it to a workers.dev URL. Nothing about Netlify changes, so there is no risk in this step.
  2. Port the seven plain functions first — consultations, messages, profile, reminders, wellness-chat, chat, get-logs. They only need env vars and outbound fetch, so they are the cheapest place to find out whether the router shape is right.
  3. Then auth and delete-account. Deliberately later: these two hold the account lifecycle, and delete-account is the only handler that uses SUPABASE_SERVICE_ROLE_KEY to do something irreversible. Exercise both against a throwaway account, not a real one.
  4. Replace Blobs with KV. Two call sites. store.setJSON(key, value) becomes env.QUERIES.put(key, JSON.stringify(value)); the read in get-logs becomes a prefix list plus get. The existing keys are <epoch-ms>-<random>, which sort usefully, so keep that shape.

    Existing blob contents are query logs, not user data. Decide whether to export them or start the KV namespace empty — starting empty is defensible and saves a migration script.

  5. Set the secrets. npx wrangler secret put <NAME> for each of the nine. Running the command is not a Login pass item; reading the value out of Supabase, Anthropic or Twilio is.
  6. Prove it on workers.dev, not locally. Sign up a throwaway account, write a journal entry, run a consultation, set a reminder, delete the account. Every integration is configured separately in production and a green local run proves none of them.
  7. Kill the Netlify cron, then add the Cloudflare one. In that order, per the warning above.
  8. Cut the domain over. Point apothecary.rosettawang.org at the Worker instead of Netlify — a Worker custom domain rather than a CNAME, so Cloudflare handles the certificate. Keep the Netlify site alive and unrouted for a week as a rollback, then delete it.

The front end may not need editing at all

index.html reaches the backend through exactly two strings: a base at line 1015, fetch('/.netlify/functions/' + path, opts), and one hardcoded '/.netlify/functions/chat' at line 956. Verified Sep 21, 2026.

So if the Worker simply routes /.netlify/functions/* itself, the front end needs no change whatsoever. The path looks odd on a host that has nothing to do with Netlify, and it can be renamed later — but a cutover that does not touch index.html is worth more than a tidy URL, for the reason in the next section.

Risk worth knowing before anyone edits the front end

support.js opens with “GENERATED from dc-runtime/src/*.ts — do not edit. Rebuild with cd dc-runtime && bun run build”, and dc-runtime/ is not in this repo. index.html loads it with <script src="./support.js">.

So a build artifact is checked in whose source is somewhere else — and if the front end ever needs rebuilding rather than patching, that source has to be found first. Not a blocker for this migration, which is why it is a note rather than a step, but it is the reason step 8 avoids touching index.html.

Done when

  1. apothecary.rosettawang.org is served by a Cloudflare Worker, with all ten endpoints answering.
  2. A throwaway account can sign up, journal, consult, set a reminder and delete itself.
  3. One reminder job runs, on Cloudflare, and Netlify's is off — confirmed by a single SMS rather than two.
  4. The Netlify site is deleted, and @netlify/blobs and @netlify/functions are out of package.json.
